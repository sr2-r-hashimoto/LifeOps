# Purpose

LifeOps exists to maximize long-term human growth.

The project treats life as an engineering problem.

Every habit, decision, workflow and system should contribute to becoming a better person over time.

Growth should be:

- Sustainable
- Measurable
- Repeatable
- Continuously improving

LifeOps is not a productivity system.

It is a human growth operating system.

# What is LifeOps?

LifeOps is a personal operating system.

The project applies software engineering, agile development, systems thinking and continuous improvement to every area of life.

This repository is intended to exist for many years.

Treat it like a production software project rather than a notebook.

---

# Primary Objective

Design systems that make good decisions easy.

The repository should reduce dependence on motivation, memory and willpower.

Success is measured by consistency.

---

# Philosophy

The repository follows these principles.

## Kaizen

Small improvements are preferred over large unsustainable changes.

Every sprint should improve something.

---

## Systems over Motivation

Do not solve problems with motivation.

Design systems that work even on bad days.

---

## Data over Emotion

Whenever possible, decisions should be based on measurable data.

Examples

- body weight
- body fat
- calories
- sleep
- expenses
- work hours
- learning hours

---

## Single Source of Truth

Every concept should have exactly one authoritative location.

Avoid duplicated documentation.

Prefer linking over copying.

---

## Maintainability

This repository is expected to live for many years.

Optimize for maintainability rather than speed.

---

# Documentation Rules

Use Markdown.

Prefer English filenames.

Headings should be concise.

Avoid unnecessary prose.

Write documents that are easy to scan.

Document decisions.

Document assumptions.

Document trade-offs.

---

# Git Rules

Use Conventional Commits.

Small commits are preferred.

History is valuable.

Do not rewrite history unless necessary.

---
